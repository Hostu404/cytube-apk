# Code Android compiles ahead of time instead of interpreting it at first,
# so the app opens and scrolls chat smoothly from the start rather than once
# it has warmed up. Installed with the app (androidx.profileinstaller) and
# compiled by Android in the background, usually while the device is idle.
#
# Libraries such as Compose, Coil, coroutines and OkHttp ship rules of their
# own; these cover what has none: the app itself, and what every chat
# message goes through (the socket connection, its HTML parser and the
# chat list's collections). Media3 is left out: it's big, and only part of
# it runs for any one video.
#
# The flags on a method: H, hot (compiled ahead of time); S, run while the
# app starts; P, run after it has. Only the code that opens the app to its
# home screen is S, and only its classes have lines of their own (L...;),
# which has them loaded with the app. With everything marked as startup
# code, as it once was here, Android can't keep the startup code together,
# which is much of what this is for. What a channel runs is H and P:
# compiled ahead of time all the same, so the first chat flood is as smooth
# as the hundredth. Of the libraries, only the parts the app uses; and the
# screens opened now and then (Settings, Account) are left to be compiled
# as they're used.
